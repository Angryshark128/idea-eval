## 第一关：红线

一票否决。命中任一即拒，不跑后续阶段。

### 法律风险

**判据**：点子利润来源依赖被法律或平台规则会堵上的漏洞。

常见情形：

- API key 中转站 — 用廉价模型冒充高价模型、或聚合转卖未经授权的 API
- 盗版资源聚合 — 影视 / 软件 / 书籍的破解版、网盘资源聚合
- 刷单刷量工具 — 刷好评、刷销量、刷粉丝、刷榜单
- 爬虫滥用 — 抓取并重新分发受版权保护的内容、绕过付费墙

**先查这些**：

- 《刑法》第 217、218、225 条（侵犯著作权、非法经营）
- 《网络安全法》《数据安全法》《个人信息保护法》
- 《电子商务法》第 12 条（平台经营者不得删除评价、不得误导欺骗用户）
- API 服务商最新的 ToS（OpenAI、Anthropic、Google、各国内大模型）
- 平台社区规则：小红书、抖音、淘宝、京东、微信公众号的最新社区规范

时效警示：API 服务商 ToS 经常改，至少 6 个月内核一次。

### 道德底线

**判据**：流量来源本身让人不舒服，或技术被滥用的概率高于被正经使用的概率。

常见情形：

- 擦边内容 / 软色情引流
- 不限制的换脸、换声、虚拟色情
- 暴力、赌博、毒品相关
- 帮人规避监管的工具（VPN、翻墙、虚拟定位）

**先查这些**：

- 《网络信息内容生态治理规定》
- 《关于加强网络视听节目平台管理的通知》
- 《互联网信息服务深度合成管理规定》（针对 deepfake）

时效警示：deepfake 监管这两年密集更新，建议每次评估都查一遍最新版。

### 合规资质

**判据**：服务一旦给到具体建议或涉及特定人群，需要相应资质，否则就是违规。

#### 证券 / 投资

- 用户问"这只股票能不能买" → 给建议 = 荐股 = 需要「证券投资咨询业务资格」
- 工具边界模糊：展示数据可以，"我建议你..."不行
- 监管口径近年趋严，"AI 选股""AI 诊股"类工具被多次约谈

**先查这些**：

- 《证券、期货投资咨询管理暂行办法》
- 《证券投资顾问业务暂行规定》
- 中国证监会官网近期行政处罚案例
- 搜索「AI 荐股 处罚」「AI 投资咨询 合规」最近 6 个月新闻

#### 医疗

- 用户描述症状，工具给诊断 / 用药建议 → 诊疗行为 → 需要医疗机构资质 + 医师执业证
- 信息聚合（疾病百科、检查报告解读）可以，主动建议不行
- AI 辅助诊断边界在法规层面正在收紧

**先查这些**：

- 《互联网诊疗管理办法（试行）》《互联网医院管理办法（试行）》
- 国家卫健委、国家药监局近期政策
- 《生成式人工智能服务管理暂行办法》（涉医条款）
- 搜索「AI 医疗 合规」「互联网诊疗 监管」近期

#### 教育 / K12

- 学科类辅导需要办学许可 + 教师资格证
- 素质类（编程、绘画、音乐）目前门槛低，但部分省份在收紧
- "AI 辅导" 类工具的合规边界尚未完全明确，但风险高

**先查这些**：

- 《民办教育促进法》《民办教育促进法实施条例》
- 「双减」相关政策文件原文
- 当地教育厅 / 教委最新通知

#### 食品 / 保健品 / 药品

- 功效宣称受《广告法》《食品安全法》严格限制
- "治疗""预防""根治"等词几乎都违规

**先查这些**：

- 《广告法》第十七、十八条
- 国家市场监督管理总局近期典型案例

#### 数据 / 跨境

- 收集个人信息要遵循最小必要原则
- 数据出境需要通过安全评估 / 标准合同 / 认证
- 训练数据来源合法性是 AI 产品的高频雷区

**先查这些**：

- 《个人信息保护法》《数据出境安全评估办法》
- 《生成式人工智能服务管理暂行办法》（训练数据条款）
- 网信办近期算法备案清单

**轨迹陷阱**：这条红线不是静态的。"我只是做信息聚合" → 加一个"我建议..."功能 → 越界。每次规划都要审计轨迹，不是只看启动快照。

### 技术不可控

**判据**：AI 错误答案会让用户付出真实代价（钱、健康、自由），当前 AI 可靠性不够。

高风险场景：

- 医疗诊断 / 用药建议
- 法律建议 / 合同条款解释
- 投资建议 / 交易决策
- 自动驾驶 / 工业控制
- 涉及人身安全的物理动作

**先查这些**（评估 AI 当前能力时必须看的）：

- LMSYS Chatbot Arena 排行榜（综合人类偏好评测）
- HuggingFace Open LLM Leaderboard（学术基准）
- 各家大模型厂商的技术报告（幻觉率、数学 / 推理 / 代码能力）
- 医疗 / 法律 / 金融场景的第三方评测论文（PubMed、arXiv、Google Scholar 搜「LLM hallucination medical」「LLM legal advice accuracy」）
- 网信办 / 行业自律组织的近期评估报告

时效警示：模型能力半年一变。每 6 个月或每次发新版主流模型时重新评估一次。

## 第二关：定位

三选一，每个桶给第三、第四关分配不同权重。定错桶，后面全跑偏。

### 技术影响力

- 目标：做出有技术深度的东西，建立社区口碑
- 权重：技术深度、创新性高
- 权重：商业回报低（不是零，但不是成功指标）
- 成本容忍度：高

示例：实时协同编辑器、新型数据库引擎、新协议实现。可以开源。成功信号是社区认可度，不是收入。

### 可商业化变现

- 目标：最终赚钱，前期可接受不赚钱
- 权重：商业价值、成本控制高
- 权重：技术深度中等——能用成熟方案就不自己造轮子
- 成本容忍度：低到中等——每项支出都要拉得动回报

示例：垂直行业 SaaS、专业工具订阅、交易型服务。成功信号是收入与留存。

### 纯粹想做点能被人用的东西

- 目标：做出有用的东西，有人用，包括自己用
- 权重："有没有人用"、"自己开不开心"
- 权重：商业回报无关
- 成本容忍度：高

示例：个人笔记工具、解决自己痛点的开发工具。成功信号是"自己每天用 + N 个别人每周用"，N 可以很小。

### 怎么选

问用户："如果只能选一个 2 年后看重的成功信号——社区认可 / 付费用户 / 个人成就感——选哪个？"答案就是桶。

## 第三关：价值

三问一陷阱。每问都有可证伪的小实验。

### 真实问题？

**可证伪实验**：找 10 个目标用户问"现在怎么处理 X？"

- 答"我忍着""我用 Excel 凑合""我们有个半残内部工具" → 真问题
- 答"从没想过这个问题" → 大概率伪需求

找不到愿意聊的 10 个人 → 要么市场太小（可以接受），要么在想象用户（红旗）。

**先查这些**：

- 目标用户常驻社群：Reddit 子版、V2EX 节点、即刻圈子、掘金 / CSDN / InfoQ 评论、知乎回答、相关微信公众号留言
- App Store / Google Play / 微信小程序的同类应用评论区（差评最有用）
- 知乎、Quora 上"怎么解决 X"类问题与回答
- 关键词：「[痛点关键词] 痛」「[痛点关键词] 难用」「[痛点关键词] 工作流」

### 现有方案够好？

不是"没有方案"。大多数市场已经有 3+ 选项。门槛是其中之一：

- 太贵（商业：SMB 买不起企业版的细分市场）
- 太复杂（技术：陡峭学习曲线的开发者工具）
- 太慢（流程：能自动化的手工操作）
- 缺关键功能（任何领域：现有产品不覆盖的角落）

加 AI 自动分类不算够差。改善必须大到让人愿意迁移。

**可证伪实验**：找现有 top 3 方案自己用一周。写下每个让你挫败的具体点。写不出来 → 你以为的差距不存在。

**先查这些**：

- Product Hunt 上同类应用
- G2、Capterra 上的差评（差评揭示用户最痛点）
- 「[竞品] vs [竞品]」对比评测文章
- 国内：36氪、虎嗅、少数派的深度评测
- GitHub 上同类开源项目的 issue 列表（高频 issue 就是用户痛）

### 人群够大？

小众可以，大众不是必需。门槛是"足够活跃或付费用户支撑项目持续成本 + 你的时间"。

独立开发者优势：服务大公司看不上的小市场（5 位数用户基数就够）。

**先查这些**：

- 行业报告：艾瑞、易观、QuestMobile 的相关行业白皮书
- 目标用户群在即刻 / 微信群 / Discord / Slack 的实际规模
- 现有同类产品的真实用户量（App Annie、SimilarWeb、七麦数据）

### 陷阱：蓝海 vs 死海

"没人做"可能是：

- 蓝海：真需求但没人搞定服务方式
- 死海：没需求，所以没人来

**怎么区分**：

- 搜论坛、Reddit、社群、邻近工具的用户评论，找底层需求
- 找"抱怨""凑合""希望有这个""要是能 X 就好了"的措辞
- 连抱怨都没有 → 大概率死海

有 5 个平庸竞品的市场比 0 个竞品的市场健康。

## 第四关：难度 × 成本

### 难度

每个主要组件问：

1. 我能在一段合理时间内从零写出来吗？
2. 不能 → 在项目时间窗内能学会吗？
3. 不能 → 有可靠的替代吗（库 / 服务 / 合作方）？

关键组件三个都答否 → 点子超出你的难度预算。

**先查这些**（评估"能不能学"时）：

- 主流学习资源：官方文档、MDN、Real Python、freeCodeCamp
- 中文社区：掘金、CSDN、思否、知乎专栏
- 相关 GitHub 仓库的 star / fork / issue 活跃度（看社区规模）

### 成本：7 类

每项都要查当前真实定价，不靠印象。

#### 1. 服务器 / 基础设施

**先查这些**：

- 主流云厂商定价页：阿里云、腾讯云、AWS、华为云
- 国内轻量应用服务器、对象存储、CDN、数据库的最新折扣
- Vercel / Netlify / Railway / Fly.io 等 PaaS 的 hobby / pro 档

时效警示：云厂商经常调价，至少季度核一次。

#### 2. 第三方 API 订阅

**先查这些**：

- 各 AI 模型厂商定价：OpenAI、Anthropic、Google、DeepSeek、通义、文心、Kimi
- 支付：Stripe、支付宝、微信支付、Paddle（海外）
- 邮件：SendGrid、Mailgun、Postmark、Resend
- 短信：阿里云、腾讯云、Twilio
- 监控：Sentry、Datadog、PagerDuty

每类至少核两家以上做对比。注意按量计费的小额账单陷阱。

#### 3. 一次性

域名、SSL 证书、设计资源、开发工具订阅。钱小但别忘算。

#### 4. 维护

持续投入。估算为开发时间的 10–20%。

#### 5. 分发

冷启动时通常 > 技术成本。

**先查这些**：

- SEO 工具：Ahrefs、SEMrush 的关键词难度
- 内容平台分发策略：小红书、知乎、公众号、B 站、抖音、Medium、dev.to
- 社区投放成本：Product Hunt Launch Day、V2EX、Reddit、Hacker News、Show HN 历史数据

#### 6. 冷启动

0 → 第一批种子用户。时间投入最大、即时回报最小。

预先估算：能扛几周零回报的独自打磨？

#### 7. 运营

用户来了之后，客服、社群、反馈处理吃时间。往往是 solo dev 第一个烧垮的环节。

### 未知成本陷阱

任何能单方面变化的东西：

- 爬虫：反爬规则变 → 工具失效
- 第三方 API：涨价 / 限流 / 停服
- 平台规则：应用商店、支付通道、社交平台
- 监管：数据隐私、AI 法规

每个依赖问："明天变了，对我影响多大？"答"项目死了"→ 重新设计依赖再写。

### 边界预设

写代码前写下不做什么。例：

- v1 不做移动端，只做 web
- v1 不做多租户，单用户
- v1 不做支付，免费测试期
- v1 不做国际化，只做中文

每个"能不能也加个 X"的小需求单独看不大，叠加起来远超原始设计。

## 第五关：框架退场

框架决定不了：

- ROI 门槛（多少回报 / 单位时间算够？）
- 时间窗口（要多久出结果？）
- 机会成本（这事会挤掉什么？）
- 个人契合度（这事跟我的兴趣 / 生活状况合不合？）

这些是个人价值观，不是框架输入。每项问用户拿答案，再给建议。
