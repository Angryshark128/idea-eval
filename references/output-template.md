# 输出模板

评估报告的结构。每条结论后跟来源链接与核实日期。报告保持紧凑——每阶段一段，不写废话墙。

```markdown
# 点子评估：<点子名称>

**提交人**：<用户或"self">
**日期**：<YYYY-MM-DD>
**轮次**：<1, 2, ...>

## 结论

[通过 | 待修订 | 否决]

一行理由：<为什么是这个结论>

## 第一关：红线

| 类别 | 状态 | 证据 + 来源（核实日期） |
|------|------|------------------------|
| 法律风险 | clear / concern: <细节> | <法规名 / 链接 / YYYY-MM-DD> |
| 道德底线 | clear / concern: <细节> | <来源 / YYYY-MM-DD> |
| 合规资质 | clear / concern: <细节> | <法规 / 处罚案例 / YYYY-MM-DD> |
| 技术不可控 | clear / concern: <细节> | <能力评测 / YYYY-MM-DD> |

任一 concern → 本关 否决，后四关不跑。

## 第二关：定位

桶：[技术影响力 | 可商业化变现 | 纯粹想做点能被人用的东西]

权重影响（来源：用户回答 / 自身判断）：

- 技术深度：[高 | 中 | 低]
- 商业回报：[高 | 中 | 低 | 不适用]
- 成本容忍度：[高 | 中 | 低]

## 第三关：价值

| 问题 | 结论 | 证据 + 来源（核实日期） |
|------|------|------------------------|
| 真实问题？ | 是 / 部分 / 否 | <用户访谈摘要 / 社群贴子链接 / YYYY-MM-DD> |
| 现有方案够好？ | 是 / 部分 / 否 | <评测文章 / 竞品差评 / YYYY-MM-DD> |
| 人群够大？ | 是 / 部分 / 否 | <行业报告 / 用户量数据 / YYYY-MM-DD> |

蓝海 vs 死海检查：<一段话，引述证据>

## 第四关：难度 × 成本

**难度结论**：[在预算内 | 可学 | 超出]

逐组件：

- <组件 1>：能从零写？<Y/N + 来源：官方文档>；能学？<Y/N + 来源：教程>；有替代？<Y/N + 来源：库名>
- <组件 2>：...

**成本估算**（除标注外按月）：

| 类别 | 估算 | 依据来源（核实日期） |
|------|------|---------------------|
| 服务器 / 基础设施 | ¥ | <云厂商定价页 / YYYY-MM-DD> |
| 第三方 API 订阅 | ¥ | <厂商定价页 / YYYY-MM-DD> |
| 一次性 | ¥ | <域名 / 证书实际价格> |
| 维护 | 小时/月 | <历史项目经验> |
| 分发 | ¥ | <SEO 工具数据 / 投放历史> |
| 冷启动跑道 | 周 | <竞品冷启动公开数据> |
| 运营 | 小时/月 | <历史项目经验> |

**未知成本风险**：<列出能单方面变化的依赖，每项给来源>

**预设边界**：

- v1 不做：<清单>
- v1 做：<清单>

## 第五关：框架退场（个人判断）

用户决定：

- ROI 门槛：<用户答>
- 时间窗口：<用户答>
- 机会成本：<用户答>
- 个人契合度：<用户答>

## 建议

<2–4 句自由文本。结论如上，这里解释理由 + 指出用户最该想清楚的下一件事。>

## 时效声明

本次评估引用的所有事实核实日期：<YYYY-MM-DD>

下次复核建议时间：<YYYY-MM-DD，按各源时效取最短>

## 下一轮（可选）

下一轮要重评的部分：

- <什么该改>
- <要收集什么新证据>
```

## 结论定义

- **通过**：5 关全清。值得投入时间。
- **待修订**：第一到第四关基本清，但有 1 处以上需要解决（定位不清、成本与收益不匹配、难度临界）。让用户重塑范围后再跑。
- **否决**：任一红线命中，或第三 / 第四关有致命问题（伪需求、无人群、成本远超收益、难度超出）。

不软化 否决。框架说不行就不行。

## 信息缺失时的写法

查不到关键事实 → 标"未核实"而不是猜：

```
| 第三方 API 订阅 | ¥?（未核实） | 需查 <厂商定价页> |
```

报告里出现 3 处以上"未核实"且都涉及关键判据 → 报告末尾追加：

```
## 警告
本次评估有 N 处关键信息未核实，建议补查后重新评估。建议补查源：<列出>
```

## 长度指引

- 点子描述一两段：完整报告，约 300 字
- 中等点子（带背景）：完整报告，约 500 字
- 详细点子（用户已写设计稿）：每阶段一段总结，约 200 字 + 引用设计稿证据

不灌水，用户是扫读的。
